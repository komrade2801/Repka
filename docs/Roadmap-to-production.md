# Roadmap to production

План развития AI-native системы управления проектами **Repka** до боевого состояния (в т.ч. требования заказчика / BIOCAD). Документ фиксирует: что уже в MVP, что **намеренно не делаем**, приоритеты P0–P2 и обязательные пробелы, которые нельзя упустить.

См. также этапы MVP в [plan.md](./plan.md).

---

## Уже в MVP (baseline)

- React + FastAPI + MCP + LLM (OpenRouter), tool calling без полного snapshot плана
- Диаграмма Ганта, CRUD, append-импорт / экспорт Excel
- Чат: search/summary + мутации (в т.ч. bulk); зависимости — слой A (граф без автосдвига дат)
- Rate limiting на mutate/`/chat`, лимиты полей, CORS из env
- Деплой: Vercel (UI) + Render (API); URL — вне репозитория

---

## Что нецелесообразно (пересмотр / вне scope ранних фаз)

### Карточный вид Trello-like (Канбан «на Ганте»)

Гантт и Канбан опираются на разные ментальные модели и сущности. В Канбане критичны статусы (To Do / In Progress / Done), которых **нет** в текущей модели `Task`. Гибрид «всё-в-одном» на раннем этапе переусложнит UI/UX без реальной ценности.

**Решение:** исключить из P0–P1. Система остаётся сфокусированной на **временнóй** аналитике и планировании (Гант / Timeline).

### Подгон под все методологии сразу (Waterfall + Kanban + Спринты)

Классический Гантт (вехи, FS) противоречит непрерывному потоку Kanban и итерациям Scrum. Попытка закрыть все методологии одним продуктом даёт расфокусировку.

**Решение:** фокус на **Waterfall / Hybrid Project Management** (вехи, зависимости FS, критический путь) — зона максимального рычага Ганта + AI-агента.

### Внедрение LangChain «ради оркестрации»

Уже есть лёгкий цикл tool calling: `mcp_tools.py` + OpenAI SDK (`agent.py`), лимит раундов, grounding, tool stripping. Тяжёлый LangChain увеличит latency и сложность абстракций без явной выгоды.

**Решение:** не тащить LangChain. Вместо этого — **контролируемые Guardrails** (лёгкие библиотеки вроде NeMo Guardrails / pydantic-валидация, либо микросервис) поверх текущего MCP + Pydantic.

## P0 — Critical Path (выход в Prod / baseline Enterprise)

Фундаментальная надёжность, безопасность и базовые требования заказчика.

### 1. UI/UX: ребрендинг под брендбук BIOCAD

- Палитра (корпоративный синий / белый / акцент), шрифты (Inter / Geist), логотип (BIOCAD Identity)
- Кастомизация shadcn под токены бренда / UI-kit компании

### 2. Инфраструктура и безопасность

| Тема | Сейчас (MVP) | Prod |
| --- | --- | --- |
| БД | SQLite (на Render без диска — эфемерна) | Managed **PostgreSQL** + драйвер в `requirements.txt` |
| Миграции | `create_all` + SQLite `ALTER` | **Alembic** |
| ID задач | `int` autoincrement | **UUID** (анти-перебор, распределённая работа) |
| Зависимости | Строка `"1,2"` | Join-таблица `task_dependencies` (желательно вместе с UUID) |
| Auth | Нет | SSO / OAuth2 / SAML / LDAP (Keycloak / AD); **RBAC**: Viewer / Editor / Admin |
| DR | Нет | Daily-бэкапы Postgres, проверка **PITR** |
| Secure SDLC | Нет | SAST/DAST, Dependabot / Trivy / Bandit в CI/CD |

### 3. Диаграмма Ганта (core fixes)

- Корректная отрисовка связей FS (стрелки без наложений)
- Дефолтная сортировка задач по `start_date` ↑
- Сплошной вид **Timeline**: непрерывный горизонтальный скролл без жёстких скачков `viewDate`

## P1 — High Value (автоматизация и аналитика)

### 1. AI-агент и генерация задач

- Генерация WBS / плана из текста, протоколов встреч, транскриптов (отдельный эндпоинт + промпт)
- **`bulk_create_tasks`** — пакетное создание: аргумент `tasks: [{title, start_date, duration, assignee?, priority?}, …]` (десятки задач за один вызов БД вместо серии `create_task`). Агент парсит протокол созвона / ТЗ → один tool call → commit пачки; валидация слоя A на весь батч, частичный rollback при ошибке графа
- Выделение `agent` + `mcp_tools` в **микросервис** с входной/выходной валидацией (Guardrails, защита от ПДн, фильтрация опасных мутаций)

### 2. Расширенные виды Ганта и группировка

- Иерархия Epic / Parent → Subtask, сворачивание групп
- Поле `progress` (0–100%) и визуализация на барах
- Режим «чистая интерактивная таблица» (Excel-like) рядом с «Гант + таблица»
- DatePicker для прыжка к дате / неделе / месяцу на таймлайне

### 3. Наблюдаемость и хранение

- Prometheus/Grafana и/или Sentry; метрики токенов и latency LLM
- Поле attachments / links (S3, записи созвонов, ТЗ)

## Обязательные дополнения (не упустить в Prod)

Эти пункты критичны для руководства/заказчика и бизнес-логики Ганта — даже если их не было в первом «wish-list».

### 1. Слой B — автосдвиг зависимых (auto-scheduling)

**Проблема:** при переносе предшественника ведомые задачи не двигаются → ломается Finish-to-Start.

**Решение:** каскадный пересчёт при ручном сдвиге и через AI — MCP `shift_with_cascade` / флаг `move_task(..., shift_dependents=True)`; массовые цепочки — `bulk_add_dependencies` (см. [MCP Tools на будущее](#mcp-tools-на-будущее)).

### 2. Критический путь (CPM)

Подсветка задач, задержка которых сдвигает срок всего проекта — особенно ценно для R&D / фармы. На стороне агента: `get_critical_path`, what-if через `simulate_delay` (без записи в БД).

### 3. Human-in-the-Loop для критических AI-мутаций

`bulk_delete_tasks` / `bulk_move_tasks` (и аналоги) — **Confirmation Modal** в UI до применения. Снижает риск порчи плана галлюцинацией агента.

### 4. Пакетная генерация и импорт (`bulk_create_tasks`)

Сейчас агент создаёт задачи по одной через `create_task` (до 6 раундов tool calling) — неудобно для разбора протокола/ТЗ на 10–20 задач. Нужен MCP-tool **`bulk_create_tasks(tasks[])`**: один сетевой round-trip к БД, общая транзакция, лимит размера батча (как у других bulk, ~250), HITL при больших пачках (см. п. 3).

Связано с P1 §1 и с merge/upsert Excel (п. 5): текстовая генерация и файловый импорт должны сходиться в одну модель создания пачки.

### 5. Политика импорта Excel: Merge / Upsert

Сейчас только **append** уникальных `title`. В проде нужен merge/upsert по стабильному внешнему ID (и явная политика конфликтов), чтобы обновлять существующие планы из Excel.

### 6. Data Privacy & On-Prem LLM

BIOCAD / фармконтур: жёсткие требования ИБ. Переход с внешнего OpenRouter на **внутренний** LLM (vLLM / корпоративный AI API), чтобы не утекали чувствительные данные R&D.

## MCP Tools на будущее

Ручки для усложнения бизнес-логики Ганта (слой B), иерархии и аналитики. Реализуются после baseline P0 и вместе с пунктами выше; текущий набор tools — в [agent-mcp.md](./agent-mcp.md).

### 1. Управление каскадом и связями (Smart Rescheduling)

| Tool | Назначение |
| --- | --- |
| `shift_with_cascade(task_id, offset_days)` | Сдвиг задачи + каскадный перенос всех ведомых по графу зависимостей (сохранение Finish-to-Start; ядро слоя B) |
| `bulk_add_dependencies(chain_task_ids)` | Связать список в одну цепочку A → B → C за один вызов (вместо серии `add_dependency`) |

### 2. Иерархия, группировка и шаблоны

| Tool | Назначение |
| --- | --- |
| `set_parent_task(task_ids, parent_id)` / `group_tasks` | Привязка к эпикам / родительским группам (нужна модель Parent/Epic — P1 §2) |
| `duplicate_task_structure(group_id \| task_ids, new_start_date)` | Клон шаблона («Релиз фичи») на новую дату со сдвигом дат и внутренних связей |

### 3. Умная аналитика и поиск узких мест

| Tool | Назначение |
| --- | --- |
| `get_conflicts_or_overlaps(assignee?)` | Накладки: дни, когда у исполнителя несколько параллельных задач |
| `get_critical_path()` | Цепочка задач, определяющая дедлайн проекта (CPM, см. п. 2 выше) |
| `simulate_delay(task_id, delay_days)` | What-if: влияние задержки X на N дней на финиш проекта **без** записи в БД |

## Риски (кратко)

| Риск | Митигация |
| --- | --- |
| Abuse / стоимость LLM без auth | RBAC, квоты, Guardrails, on-prem LLM |
| Галлюцинации агента на bulk-мутациях | HITL-подтверждения, валидация аргументов |
| Потеря данных SQLite | Postgres + бэкапы / PITR |
| Cold start хостинга | Платный инстанс, warm-up, UX «агент думает» |
| Расфокусировка продукта | Держать Waterfall/Hybrid; Канбан/мультиметодологии — вне P0–P1 |

## Рекомендуемый порядок закрытия

1. **P0 инфраструктура:** Postgres + Alembic + UUID + бэкапы/PITR  
2. **P0 безопасность:** SSO/RBAC + CI security scanning  
3. **P0 Гантт core:** связи FS, сортировка, Timeline  
4. **Бизнес-логика Ганта:** слой B (`shift_with_cascade`, `bulk_add_dependencies`) + CPM (`get_critical_path`, `simulate_delay`)  
5. **HITL** на bulk AI-мутациях + `bulk_create_tasks` + Merge/Upsert импорт  
6. **BIOCAD UI** + on-prem LLM / Guardrails-контур агента  
7. **P1** иерархия/шаблоны (`set_parent_task`, `duplicate_task_structure`), overlaps, WBS-генерация, observability  
8. **P2** интеграции, workload, экспорт снимков, мобильность  

Итоговая продуктовая рамка до масштабирования: **Гант + зависимости + AI-агент с контролем**, а не «ещё один Канбан/Jira».
